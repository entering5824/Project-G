# Genshin Account Progression Planner — Game Data Specification v1

## 1. Mục tiêu của Game Data Layer

Game Data Layer lưu **dữ liệu khách quan của game**, độc lập hoàn toàn với account của người dùng.

Nó trả lời các câu hỏi:

```text
Character X cần gì để ascension?
Talent Y từ 8 → 9 cần gì?
Weapon Z từ 20 → 90 cần gì?
Material này farm ở đâu?
Domain nào drop material này?
Domain mở ngày nào?
Artifact set này nằm ở domain nào?
Boss nào drop material này?
```

Game Data **không chứa**:

```text
account hiện tại
tier list cá nhân
priority
Akasha RV
saved teams
material inventory cá nhân
planner score
```

---

# 2. Kiến trúc dữ liệu

```text
External Game Data
       ↓
Game Data Importer
       ↓
Normalizer
       ↓
Canonical GameData
       ↓
Database / JSON Cache
       ↓
Planner / Cost Engine / Scheduler
```

Planner tuyệt đối không gọi trực tiếp API bên ngoài.

Planner chỉ làm việc với:

```python
GameDataRepository
```

# 4. Character Definition

```python
class CharacterDefinition:
    key: str
    name: str

    rarity: int
    element: str
    weapon_type: str

    region: str | None

    local_specialty: str | None
    normal_boss_material: str | None

    talent_book_family: str | None
    weekly_boss_materials: list[str]

    ascension_material_family: str | None
    common_enemy_material_family: str | None
```

Ví dụ logic:

```text
Fischl
├── Ascension boss material
├── Local specialty
├── Enemy drop family
├── Talent book family
└── Weekly boss material
```

Không cần copy descriptive lore.

Chỉ lưu dữ liệu liên quan tới progression.

# 6. Talent Upgrade Cost

Talent cost phải lưu **theo từng level step**.

Không chỉ:

```text
1 → 10 total
```

Mà:

```text
1 → 2
2 → 3
3 → 4
...
9 → 10
```

Schema:

```python
class TalentUpgradeCost:
    character_key: str

    from_level: int
    to_level: int

    mora: int

    talent_books: dict[str, int]
    enemy_materials: dict[str, int]
    weekly_materials: dict[str, int]
    crown: int
```

Nếu Planner muốn:

```text
Skill 8 → 10
```

Cost Engine tính:

```text
cost(8→9)
+
cost(9→10)
```

# 13. Crafting Conversion

Planner nên biết:

```text
3 low → 1 medium
3 medium → 1 high
```

Schema:

```python
class CraftRecipe:
    output_material: str
    output_amount: int

    inputs: dict[str, int]
```

Cost Resolver phải tính được:

```text
Inventory:
Low  = 90
Mid  = 0
High = 0
```

nhưng requirement:

```text
High = 10
```

thì không kết luận ngay:

```text
thiếu 10 high
```

mà biết:

```text
90 low
→ 30 mid
→ 10 high
```

=> đủ.

# 17. Sunday Rule

Sunday thường có tất cả material rotations tương ứng.

Không cần duplicate data cho Sunday.

Scheduler có thể hiểu:

```text

→ Monday
→ Thursday
→ Sunday
```

Tương tự:

```text
TUE_FRI
WED_SAT
```

# 31. Normalized Material Units

Để estimate dễ hơn, convert các tier material về lowest-tier-equivalent.

Ví dụ:

```text
Green = 1
Blue  = 3
Purple = 9
```

Requirement:

```text
2 Purple
```

=

```text
18 base units
```

Inventory:

```text
1 Purple
2 Blue
3 Green
```

=

```text
9 + 6 + 3 = 18
```

=> đủ.

Cost Engine cực dễ xử lý.

```text

↓

↓

↓

↓
```


# 46. Validation

Update GameData phải validate:

```text
character target references valid materials

weapon references valid materials

material domain exists

artifact domain exists

cost levels contiguous

```

```text

8→9
```

nếu thiếu:

```text
9→10
```
